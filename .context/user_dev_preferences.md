교회 고등부 출석/수련회 관리 시스템을 운영하는 개발자. 4개 Firebase 앱을 혼자 관리 중.

- **DB 안전성을 최우선으로 생각함** — 코드 변경 시 항상 "DB가 꼬일 여지가 있는지" 먼저 확인함
- 기능 변경 전 반드시 영향 범위를 설명받고 싶어함 ("실행은 하지말고 설명만 해줘봐")
- 확인 후 "진행해줘"라고 하면 구현 + 타입체크 + 테스트 + 배포까지 한번에 원함
- 웹 개발 기본 개념(SSR, API Route 등)은 설명이 필요한 수준 — 비유와 프로젝트 맥락으로 설명하면 잘 이해함
- 한국어로 소통, 코드 주석도 한국어 선호
- 여러 작업을 한번에 진행하는 것을 선호 ("둘 다 진행해줘", "전체 한번에")

**How to apply:** 코드 변경 제안 시 항상 DB 영향 여부를 먼저 언급. 복잡한 개념은 이 프로젝트에 맞춰 쉽게 설명. 작업 완료 후 배포 여부를 물어볼 것.
