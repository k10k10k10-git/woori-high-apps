# 찬양팀 주간 업무 연결 개선 — 2026-09-08

## 사용자에게 달라지는 흐름

- 첫 화면은 선택한 모임의 다음 업무를 먼저 안내한다. 조 미확정 → 담당 출결 → 본인 주일 참석 → 등단 준비·확인으로 이어지며, 권한에 없는 일을 권하지 않는다.
- 휴강은 자동 추천에서 제외한다. 명시 선택한 휴강·과거 회차는 유지하고 보관 안내를 표시한다. 조회에서 빠진 담당 출석을 미입력이나 완료로 단정하지 않는다. 연결이 무효인 출석도 완료 수에 포함하지 않는다.
- 조편성 바로가기는 팀원 목록을 거치지 않고 조편성으로 이동한다. 방문한 편집기는 기존처럼 유지하고 조/무대 초안 가드·멱등 저장·revision 검증을 보존한다.
- 학기 명단 링크에 연결 학기·팀·workspace·모임을 담는다. 배치 화면은 해당 팀에 집중해 열리고 전체 팀을 다시 선택할 수 있다. 복귀 링크는 동일 workspace와 모임으로 연결하며 임의 외부 return URL을 받지 않는다.
- 이관 기준 시각·회차/명단 연결 수·첨부 원본 및 과거 조 확인 항목은 운영 설정에 모은다. 주간 화면에는 로그인 연결 미완료처럼 실제 운영에 필요한 안내만 표시한다.
- 운영 책임자에게만 제공하는 계정 목록은 등록 이름·이메일·역할 설명으로 동명이인을 구분한다. 이메일이 없는 계정은 확인 필요로 표시한다. 이름을 근거로 계정을 자동 연결하거나 권한을 부여하지 않는다.
- 진행 안내·인쇄 자료는 필요할 때 펼쳐서 확인한다. PC·모바일 모두 기존 밝은/어두운 테마와 공간형 무대·목록 편집을 유지한다.

## 검증과 운영 경계

통합 앱의 lint → typecheck → 전체 test → build를 순차 실행한다. 최종 수치와 배포 SHA는 PR 및 로컬 `outputs/praise-flow-20260908/` 영수증에 기록한다. 회귀 검사는 권한별 출결 집계, 휴강 추천, 비활성/중복 계정 집계, 조 바로가기, 팀 필터 해제, 삭제된 팀 링크, 복귀 URL 검증, 승인 계정 목록의 최소 필드를 포함한다.

브라우저 검사는 실제 PraiseWorkspace·AssignTab과 앱 CSS를 사용하되 인증·DB·찬양 API만 합성 구현으로 교체한다. 합성 33학생·10스탭으로 화면 구조와 이동을 검증하며 운영 저장 성공으로 기록하지 않는다. 운영 배포 후 버전 대조와 로그인된 실제 화면의 읽기·이동도 별도로 확인한다.

- 운영 DB 직접 쓰기, 계정 권한 부여, Rules 변경·배포는 없다. 새 DB 노드나 공통 원장 스키마 변경도 없다.
- 기존 입력·확정·동시성 계약은 유지한다. 현재 작업은 완전한 과거 자료 복제, 기존 사이트 관리자 입력의 기술적 차단, 운영자 전체 실사용 테스트를 완료한 것으로 간주하지 않는다.
- 담당 스탭의 실제 계정 연결은 별도 승인과 사전 스냅샷을 필요로 한다. 계정 선택 도구 개선과 운영 계정 적용은 구분한다.
