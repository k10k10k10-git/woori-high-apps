## 남은 위험과 후속 권고

- **P1 접근 정책**: 기존 공용 로그인은 공개 빌드의 공용 자격정보와 실제 원장 권한을 사용한다.
  UI에서 반/관리자 메뉴를 숨기는 것은 DB 접근 제한이 아니다. 개인 교사 계정/반별 최소권한으로
  전환하고 공용 계정 권한·자격정보를 회수하는 것이 가장 중요한 후속 조치다.
  이는 계정/운영 권한 변경이므로 이번 Hosting 개선에 섞어 실행하지 않았다.
- **P2 운영 설정의 장기 쓰기**: 일부 기존 관리자 설정/삭제는 SDK 기반이다. 서버 잠금·스냅샷으로
  보호된 학생 이동/복구와 달리 모든 관리자 쓰기를 오프라인 큐까지 포함한 하나의 버전 체계로
  완전히 묶은 것은 아니다. 안전한 조건부 저장을 작은 업무 단위로 계속 확대하는 편이 좋다.
- **P2 개발 의존성**: `npm audit` 전체 검사에는 개발 의존성 8건(높음 6/보통 2)이 남았다.
  Vitest mock 서버/패턴 처리 계열이며 운영 정적 사이트에는 포함되지 않는다.
  테스트 프레임워크 메이저 업그레이드/상위 패치가 필요한 항목을 무조건 force downgrade하지 않았다.
  개발 서버는 loopback 전용으로 두고 외부에 노출하지 않는다. 운영 의존성 검사는 0건이다.
- **P2 검증 환경**: Ego Lite의 DOM/상호작용은 동작했지만 화면 캡처가 반복 시간 초과했다.
  캡처 기반 시각 검증을 통과로 표시하지 않는다. 실제 iPhone/Android·VoiceOver/NVDA,
  장기간 단절/재연결과 운영 권한별 E2E는 별도 현장 확인 대상이다.
- **P3 구조**: 라이트 업무 UI의 개별 CSS 토큰 중복과 큰 `AttendanceTab`/`AdminTab`는 남았다.
  한 번에 재작성하기보다 업무별 컴포넌트와 회귀 검사로 분리하는 편이 안전하다.

권고 순서: 접근 정책 승인 → `$impeccable harden`(남은 관리자 조건부 저장) →
`$impeccable adapt`(실기기/확대/스크린리더) → `$impeccable optimize`(큰 원장 성능 계측) →
`$impeccable polish`(기존 시각 체계의 최종 정리).

## 실행 증거

- 최초 기준선: lint 0 오류/기존 16 경고, 타입/빌드 통과, 555 테스트 통과(에뮬레이터 10개 조건부 제외).
- 중간 개선: 592 테스트 통과, 타입/빌드 통과. 이후 대비/권한/인증 회귀를 추가했다.
- 최종 로컬 품질: lint 0 오류/기존 16 경고 → 타입 검사 → 605 테스트 통과(에뮬레이터 10개 조건부 제외) → Next 16.3.8 정적 빌드 및 운영 산출물 경계 검사 통과.
- 운영 의존성 `npm audit --omit=dev`: 0건. 개발 의존성 경고 8건은 위의 후속 과제로 구분했다.
- 운영 SDK를 차단한 1,026명 합성 명단에서 7개 화면 × 1440/390/320px, 총 21개 DOM 조합의 페이지 가로 넘침 없음. 검색·학생 상세·네트워크 로그인 오류를 확인했다. 픽셀 캡처와 실기기 확인은 제외했다.
- CI는 인증/학생 이동 회귀와 함께 심방 완료·재열기, 저장 직전 삭제, 동시 수정의 실제 ETag 계약을 격리 에뮬레이터에서 검사한다. CI 및 Hosting 배포 결과는 PR/릴리스 실행 기록으로 확인하며 로컬 테스트에 합산하지 않는다.
