# 저장소 연대기 — 이 시스템은 git보다 오래됐다

> **이 문서가 존재하는 이유:** git 이력(2026-07-02~)만 보면 이 시스템을 "두 달짜리
> 프로젝트"로 오해하게 된다. 실제로는 **첫 커밋에 이미 완성된 앱 4개, 코드 170파일**이
> 들어 있었다. 2026-09-02 세션에서 실제로 그 오해가 발생했고(조사자가 "62일 프로젝트"라고
> 보고 → 사용자가 정정), 근거를 다시 발굴해야 했다. 그 발굴 결과를 여기 남긴다.
>
> 수치는 전부 실측(git 명령 출력·파일 내용)이다. 확정할 수 없는 것은 "추정"으로 표기했다.

`2026-06-23 운영 안정화 세션` 기록 중:

```

```

**이 날이 이 프로젝트의 분기점이다.** "만들기"에서 "지키기"로 넘어갔고, 이후 나온 것이
전부 계약이다 — `DB_OWNERSHIP.md`, `paths.ts`, 계약 테스트, 그리고 현재의
`cssArchitecture.test.ts`·`componentBoundaries.test.ts`·`syncParticipants.test.ts`.

### 앱들의 순서 — 스택이 지층이다

첫 커밋 시점 4개 앱의 `package.json`:

| 앱 | 패키지명 | firebase | next | react | UI |
|---|---|---|---|---|---|
| 교사·스탭 출석부 | `woori-staff-attendance` | **^10.8.0** | **^15.3.2** | **^18.3.0** | 순수 CSS |
| 학생 출석부 | `woori-attendance-next` | ^12.15.0 | ^16.2.9 | 19.2.4 | 순수 CSS + Chart.js |

- 교사·스탭만 한 세대 뒤처진 이유: 06-23 의존성 업데이트에서 제외됐다
  (`.context/project_teacher_staff_deferred.md` — "여름수련회 이후 진행 예정").
  다만 Next 16이 있는데 Next 15로 앱을 새로 만들지는 않으므로, **가장 먼저 만들어진
  앱으로 추정**한다. `version: "1.0.0"`인 것도 이 앱뿐이다(나머지는 `0.1.0`).

  **Next.js 이전 구현이 있었음을 시사**한다. 그 구현체는 이 저장소에 없다. (추정)

문서에 명시된 의존 방향이 만들어진 순서를 말해준다:

```
학생 출석부  (classes/, attendance/ 소유 — 모든 앱의 명단 원천)
    ├──→ 교사·스탭 출석부   "교사 명단은 기존 학생 출석부 DB(classes)에서 실시간 동기화"
    └──→ 수련회 행정
             └──→ 수련회 이가드   "행정 사이트(retreat-app)가 관리하는 데이터를 읽기 전용으로 소비"
```

### 알 수 없는 것

**정확한 시작일은 복원 불가능하다.** git 이전 코드 이력이 이 저장소에 없고, 원본 앱들의
개별 저장소(있었다면)도 없다. 사용자 기억(약 6개월)이 유일한 원천이며, 위 증거는 그와
모순되지 않는다.

정황(확정 불가): `iguard/lib/types.ts`에 `레거시 키 ${staffId}__${blockId} … 2027 겨울수련회까지
읽는다`가 있어 **레거시 데이터가 실재**하고, `ministryGuideContent.ts`의 원천 자료가
`겨울수련회 조장 큐싯 · 행정시트 · 버스 자료`다. 2026년 1월 겨울수련회 무렵 이미 어떤
형태로든 돌았을 가능성을 시사하나, 개발 중 스키마 변경일 수도 있어 확정하지 않는다.

## 디자인 시스템이 지금 모양인 이유

**두 CSS 계보가 통합 앱에서 만났다.**

```
순수 CSS 계보                        Tailwind 계보
학생 출석부 (CSS 변수 시스템)          수련회 행정 (Tailwind 4)
교사·스탭   (CSS 변수 시스템)          수련회 이가드 (Tailwind 4)
        └──────────┬──────────────────────┘
                   ▼
            highschool-app
     globals.css (CSS 변수 토큰) + Tailwind 4
```

`globals.css` 성장 곡선이 그 화해의 비용을 보여준다:

```
08-05   513줄   통합 (세 앱 스타일을 한 파일에)
08-09   651줄   디자인 시스템 리뉴얼
08-10   849줄   전 화면 개편
08-16 1,982줄   ← 이가드 브랜드 색 통일. 6일 만에 +1,133줄
08-27 2,299줄   테마·상호작용 CSS 분리 (theme-compat / interaction-controls / portal-surfaces)
```

이 접합면에서 나오는 알려진 함정은 `.claude/skills/woori-portal-design/SKILL.md`의
"함정 5가지"에 정리돼 있다. 근본 원인은 습관이 아니라 **두 계보의 규칙이 하나로
합쳐지지 않은 것**이다.
