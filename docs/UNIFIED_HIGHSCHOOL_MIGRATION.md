# 고등부 통합 웹페이지 설계 및 이관 계획

## 목표

학기 사역, 수련회 행정, 수련회 현장 운영을 `highschool-app` 한 코드베이스와 한 도메인에서 제공한다. 기존 `semester-app`, `retreat-app`, `iguard-app`의 Firebase 데이터는 이동하거나 변환하지 않고 그대로 읽고 쓴다.

## 정보 구조

```text
홈
├─ 현재 진행 중인 학기
├─ 전체 일정
└─ 내 담당 사역

학기 중 사역
└─ 2026년 1학기, 2026년 2학기 …
   ├─ 훈련 출석부 / 수료 현황
   ├─ 사역팀 출석부 / 수료 현황
   ├─ 사역팀 커리큘럼
   └─ 자료 보관

방학 중 사역
└─ 2026년 겨울수련회, 2026년 여름수련회 …
   ├─ 행정팀
   └─ 이가드팀
```

관리자는 통합 홈에서 학기와 수련회를 추가할 수 있다. 일반 승인 사용자는 권한이 있는 영역만 본다.

## URL 구조

- `/`: 통합 홈
- `/semesters`: 학기 목록과 학기 생성
- `/semester/[id]`: 학기 운영
- `/retreats`: 수련회 목록과 수련회 생성
- `/retreat/[id]`: 수련회 행정
- `/retreat/[id]/field`: 수련회 이가드 현장 운영

기존 수련회 행정 URL `/retreat/[id]`는 북마크 호환을 위해 유지한다.

## 데이터 소유권

| 영역 | 유지할 경로 | 원칙 |
|---|---|---|
| 학기 사역 | `semesters/*`, `semestersPrivate/*` | 학기 모듈만 쓰기 |
| 수련회 행정 | `retreats/{id}/*`, `retreatsPrivate/{id}/*` | 행정 모듈의 기존 경로 유지 |
| 이가드 | `retreats/{id}/iguard/*` | 현장 모듈만 쓰기 |
| 공통 학생 명단 | `classes/{year}` | 읽기 전용 |
| 공통 승인 | `admins`, `retreatAdmins`, `iguardMembers`, `iguardRoles` | 기존 승인 체계 유지 |

통합은 UI와 배포 단위를 합치는 작업이다. DB 경로, 저장 형태, 민감정보 분리 원칙은 변경하지 않는다.

## 코드 구조

```text
highschool-app/src/
├─ app/                         # 단일 Next.js 라우터
│  ├─ page.tsx                  # 통합 홈
│  ├─ semesters/
│  ├─ semester/[id]/
│  ├─ retreats/
│  └─ retreat/[id]/field/
├─ features/
│  ├─ portal/                   # 홈 집계와 공통 내비게이션
│  ├─ semester/                 # 학기 도메인
│  └─ iguard/                   # 현장 운영 도메인
├─ context/                     # 통합 인증·UI 컨텍스트
└─ lib/                         # 수련회 행정 및 공통 Firebase 경로
```

기능 코드는 도메인별로 분리하되 Firebase 앱 인스턴스, 인증 상태, 디자인 토큰은 통합한다.

## 권한 모델

- `admins/{uid} = true`: 전체 관리자. 모든 영역 관리 가능.
- `retreatAdmins/{uid}`: 학기 사역과 수련회 행정 접근.
- `iguardMembers/{uid}` 및 `iguardRoles/{uid}`: 승인된 수련회 현장 기능 접근.
- 화면에서 메뉴를 숨기는 것과 별개로 기존 Firebase Rules가 최종 접근을 제한한다.

## 단계별 이관과 종료 조건

1. **통합 기반**: 새 앱, 공통 인증, 통합 홈, 학기/수련회 목록.
2. **학기 기능 편입**: 기존 학기 기능 전부를 동일 DB에서 실행.
3. **행정 기능 편입**: 현재 수련회 행정을 새 앱에서 회귀 검증.
4. **이가드 기능 편입**: 현장 기능과 PIN/팀원 권한을 새 앱에서 실행.
5. **통합 홈 완성**: 현재 학기, 전체 일정, 내 담당 사역 집계.
6. **동등성 검증**: PC·375px, 권한별 계정, 주요 저장/인쇄/동기화 시나리오 확인.
7. **전환**: 새 도메인을 운영 주소로 지정하고 기존 주소는 새 경로로 리다이렉트.
8. **안정화 후 정리**: 운영 로그와 사용자 확인을 거친 뒤에만 기존 앱 배포를 중단한다. 소스 삭제는 마지막 별도 승인 작업으로 남긴다.

## 롤백

- DB를 이관하지 않으므로 새 앱 배포에 문제가 생기면 기존 앱 주소로 즉시 복귀할 수 있다.
- 전환 전 기존 Vercel 프로젝트와 마지막 정상 배포를 유지한다.
- 새 앱에서 DB 스키마 변경이나 전체 노드 덮어쓰기를 도입하지 않는다.

## 검증 게이트

- 각 단계에서 `npx tsc --noEmit`, `npm test`, `npm run build` 통과.
- 학기: 생성, 접수, 배치, 출석, 수료, 커리큘럼, 자료 보관.
- 행정: 기존 17개 탭, 동기화, 편성, 인쇄.
- 이가드: 권한/PIN, 큐싯, 조·방·버스·인원체크, 개인 카드, 인쇄.
- 통합 홈: 현재/과거 항목 정렬, 빈 데이터, 권한별 메뉴, 모바일 내비게이션.

### 2026-08-05 동등성 검증 진행 기록

- 통합 홈에서 현재 학기·수련회·전체 일정·본인 큐싯 담당을 운영 DB 읽기로 대조했다.
- 행정 계정으로 수련회 행정 5개 그룹·17개 탭과 기존 신청 데이터 로드를 확인했다.
- 이가드 전용 계정이 학기·수련회 행정으로 진입하지 못하도록 메뉴와 직접 URL에 같은 접근 정책을 적용했고, 권한 조합 회귀 테스트를 추가했다.
- 아직 남은 전환 게이트는 이가드 전용 실제 계정 확인, 주요 저장·인쇄·실시간 갱신 시나리오, 새 운영 도메인 선정이다. 이 게이트 전에는 기존 앱을 삭제하거나 리다이렉트하지 않는다.
