# 완료 버튼 없는 출석 체크·장결 지정

## 사용자 승인과 적용일

2026-10-20 제안한 출석 방식과 탭 이동 구현·배포를 승인받았고, 신규 체크 경로와 필요한 Rules 수정·검증·배포도 별도 확인받았다. 운영 DB 직접 변경·이관·계정 권한 변경은 하지 않는다. 새 방식의 최초 주일은 2026-10-25이며 이전 주일의 빈칸은 소급 결석으로 채우지 않는다.

## 교사와 관리자

- 새 주일에는 출석 버튼 하나. 최초 미선택/기존 X는 중립, O만 초록 선택이다. 첫 체크가 저장되면 같은 일반 대상의 빈칸을 X로 함께 기록하며 선택 취소도 X다. 완료 버튼은 없고 첫 체크를 입력 완료로 표현하지 않는다.
- 페이지 조회는 쓰지 않는다. 일반 학생 전원 결석일 때만 `오늘 출석 학생 없음` 확인창을 사용한다. 이미 일반 학생 O가 있으면 기존 O를 지우지 않고 거절한다. 전원 결석과 아예 체크하지 않은 반은 다르다.
- 관리자 현황은 미시작 / 입력 있음 / 출석 0명 확인 및 최종 서버 저장 시각이다. 장결은 입력 대상에서 제외하고 기존 전체 출석 통계의 포함 기준은 유지한다. 첫 클릭 이후 남은 결석은 입력 종료를 증명하지 않는다.
- 자동 채움은 최초 체크 당시 대상 ID/personId를 따른다. 나중에 이동·추가된 학생의 과거 미입력은 자동 채우지 않고 현황 확인 대상으로 남긴다. 전원 결석을 직접 확인하는 동작만 현재 일반 명단의 빈칸 전체를 처리한다.

## 원장·동시 편집·권한

- 기존 `attendance/{year}/{classKey}/{studentId}/{weekKey}`의 O/X 형태를 유지해 통합사이트·목양·이력·Excel 통계가 같은 기록을 읽는다. 명단이나 다른 주일, 기존 O/X, 장결은 자동 채움으로 바꾸지 않는다.
- `attendanceChecks/{year}/{classKey}/{weekKey}`에는 시작/최종 서버 시각·작업 UID·작업 ID·revision·전원 결석 표시와 최초 대상 참조만 저장한다. 체크 원장/메타를 같은 root leaf PATCH에 넣고 서버에서 revision·사전 target 값·최종 target 값·다른 학생 빈칸→X 조건을 검사한다.
- 부모 쓰기를 열지 않고 metadata 필드별 무삭제 권한과 최초 roster leaf 쓰기만 허용한다. 관리자 전체/교사 본인 반만 접근하며 이동 잠금·이메일 일치·현재 학생 존재 검사를 유지한다. 교사의 명단·다른 반 쓰기는 열지 않는다.
- 기존 attendance 권한은 그대로다. Firebase `.validate`가 null 삭제에 실행되지 않는다는 한계가 있으므로 기존 클라이언트의 셀 삭제 권한을 새 기능의 완전한 감사 원장으로 설명하지 않는다. 새 API는 null을 전송하지 않고 서버 revision 경합·기존 O 덮어쓰기 거절을 실제 Emulator에서 검증한다.
- 저장 실패·결과 불명·최신값 충돌을 분리하며 오프라인 큐/자동 덮어쓰기 재시도를 추가하지 않는다. 응답 유실 뒤 재시도는 최신 기록을 확인하고 이미 반영된 작업을 중복 저장하지 않는다.
- 최초 학생 snapshot은 현재 로그인 세션의 feedback 메모리에만 유지해 재시도 대상이 바뀌지 않게 한다. targetToken은 personId 또는 영구 ID 없는 학생의 이름·생년월일 참조이며, Rules가 저장 직전 최신 명단과 비교한다. 읽은 뒤 같은 SID가 다른 사람으로 교체되면 원자 요청을 거절한다. 연락처·주소·사진을 새 체크 메타에 복사하지 않는다.
- 출석/메타 구독 두 응답 전 편집을 열지 않으며 한 구독 실패를 다른 구독 갱신으로 성공 처리하지 않는다. 계정·연도·조회 세대가 바뀌면 두 자료를 함께 비운다.

## 함께 반영

- 목양 탭: 심방 요청 → 특이사항 → 연속 결석 → 새친구. 기존 새친구 하위 탭/URL 유지.
- 일반 학생 상세에 관리자 `장결자로 지정`. 기존 복귀 확인창·동일인 검사·반 ETag 조건부 저장을 재사용해 jang 및 감사만 변경한다. 학생 ID/personId/번호/정보·모든 출석과 다른 학생을 보존한다.

## 검증·배포

단위/렌더, 실제 Auth/RTDB Emulator 계약, PC Chromium/모바일 WebKit의 최초 중립·원자 저장·재접속·취소·전원 결석·충돌·응답 유실을 확인한다. 새 주일을 재현하는 합성 시계와 과거 방식의 고정 시계를 구분한다. Rules는 운영본 백업·현재 main과 일치 확인 후 최소 변경만 배포하고 운영본을 다시 대조한 뒤 Hosting을 배포한다. 운영 학생 저장·실기기 전체 검증은 합성 검사와 구분한다. 최종 영수증은 `outputs/attendance-one-tap-20261020/RESULT.md`다.

실제 RTDB 검사에서 비캡처 그룹 정규식이 `9-3`(10월 25일)을 거절하고 `10-0`(11월 1일)만 통과하는 차이를 native Rules coverage로 확인했다. 허용 범위는 그대로 두고 캡처 그룹으로 바꾸며, 한 자리·두 자리 월 및 잘못된 주일 키를 실제 Emulator에서 함께 검사한다. 브라우저의 JavaScript 정규식 통과를 서버 호환성 검증으로 대신하지 않는다.
