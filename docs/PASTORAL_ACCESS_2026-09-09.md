# 출석부 관리자 새친구 조회 권한

사용자가 목양 리포트의 권한 오류 화면을 제시하며 출석부 관리자 계정에도 권한 부여를 요청했다. 원인은 `attendanceAdmins`가 `semesters/{sid}/newFriends` 읽기 허용 대상에 없기 때문이다.

## 승인된 변경

- 공개 새친구 원장만 읽기 추가. 학기 상위·다른 업무·비공개 심방 정보·새친구 쓰기 권한은 추가하지 않는다.
- 공용 데모도 attendanceAdmins에 들어 있으므로 `config/pastoralReport/blockedDemoUid` 1건으로 제외한다. 설정 없을 때는 추가 읽기 자체를 거절한다. 설정 쓰기는 기존 전권 admins만 허용하며 출석부 관리자·데모는 수정·삭제하지 못한다.
- 기존 운영 Rules와 소스의 변경 전 내용 일치 확인. 사전 Rules 백업은 `tmp/rules-backup/pastoral-access-before-20260909.json`. 데모 제외 설정은 사전 스냅샷 후 ETag 조건부 단건 저장·재조회한다. 학생·출석·계정 역할 레코드는 바꾸지 않는다.
- Rules 배포 후 라이브 소스 대조와 실제 관리자·데모 UID의 제한된 auth 컨텍스트로 읽기 허용·거절을 확인한다. 민감 원문·계정 ID·자격정보는 출력하거나 기록하지 않는다.

## 검증

- 정적 권한 계약 테스트, 실제 Firebase 에뮬레이터의 출석부 관리자 공개 읽기·쓰기 차단·비공개 차단·데모/교사/미등록 차단·설정 누락 차단 추가.
- 로컬 lint 0오류(기존 경고18), typecheck·build 통과. 일반 테스트363통과, Java 미설치로 에뮬레이터용6개는 CI에서 실행한다. 기존 CI 복구·활동 로그 Rules 검사를 통과한 후 배포한다.
- 화면·Hosting 산출물 변경 없이 Rules와 제외 설정만 적용하므로 기존 목양 리포트에서 다시 불러오면 된다.
