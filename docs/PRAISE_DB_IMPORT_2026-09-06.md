# 찬양팀 운영 CSV 이관 기록 — 2026-09-06

## 승인과 현재 단계

사용자가 운영 CSV를 제공하고 “DB 파일이야 읽어보고 현재 사이트에 적용해줘”라고 요청했다. 제공 기록을 기존 Firebase에 반영하는 명시 승인으로 적용한다. 원본 서비스 입력 중단·계정 권한 부여·Rules 변경은 포함하지 않는다.

이 문서 최초 작성 시점에는 원본과 변환 결과를 검증했고 운영 DB 적용은 아직 실행하지 않았다. 읽기 전용 보호 코드의 운영 배포 확인 뒤 새 원장을 생성한다. 실제 적용 결과·시각·배포 SHA는 완료 후 이 문서를 갱신한다.

## 적용 경로와 보존

- 신규 단일 경로: `praiseOps/p_import_dc53ee7b2786adbc8675`. 적용 전 값이 null임을 다시 읽어 보호된 파일에 백업하고 null 조건 transaction으로 생성한다. 같은 내용 재실행은 쓰기 없이 대조하고 다른 내용이 있으면 중단한다.
- 기존 `2026-2` 학기와 확인한 찬양팀 키를 참조한다. 학생·스탭·회차를 이름이나 날짜로 자동 병합하지 않는다. `semesters/*`, `classes/*`, 학생 출석부 원장은 쓰지 않는다.
- 원본 인물·조·모임·등단 UUID는 안정 ID로 보존한다. sourceAsOf를 표시하고 원본 작성자와 통합사이트 로그인 사용자를 동일인으로 단정하지 않는다.
- 기존 Supabase 계정과 Firebase UID 매핑이 없으므로 계정 생성·권한 부여는 0건이다. 현재 통합관리자는 기존 권한으로 이관본을 검수할 수 있다.
- 보호된 중간 파일·스냅샷은 적용과 사후 대조 뒤 삭제한다. 사용자가 제공한 Downloads 원본은 유지하고 비식별 영수증만 남긴다.

## 남은 운영 전환 조건

출석 당시 조편성 버전이 원본에 없어 `historical_group_unresolved`를 유지한다. 최신 조나 수정 시각으로 과거 소속을 추정하지 않는다. 원본 입력 중단·최종 대조가 없어 `source_snapshot_unverified`, 첨부 원본이 없어 `source_storage_incomplete`도 유지한다.

이관본은 shadow(조회·검수)다. 서버는 차단 항목이 남은 shadow의 setup/live 변경을 거부한다. 동일 행사 출석을 학기 원장과 합치는 작업과 학기·팀 화면의 전체 구조 개편은 이번 파일 이관 범위에 포함하지 않는다.
