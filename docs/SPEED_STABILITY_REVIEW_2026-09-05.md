## 속도 측정과 개선

학생 대시보드의 실제 `OverallDashboard`와 Chart.js를 loopback 브라우저에서 실행했다. Firebase 모듈은 가져오지 않고 540명·18개 반·52주의 가상 상태를 주입했다. 기존 의존성의 esbuild로 비교 번들을 만들고 같은 캔버스 생성·해제 계수기를 수정 전후에 적용했다.

| 조작 또는 재현 | 수정 전 | 수정 후 |
|---|---|---|
| 주차별 학년 차트의 부서 1부→2부 전환 | 차트 생성 4회·해제 4회 | 해당 차트만 생성 1회·해제 1회 |
| 학년별 월별 출석률의 부서 전환 | 한 effect에 차트 4개가 묶임 | 브라우저에서 생성 1회·해제 1회 확인 |
| 포털 수련회 이름 50회 변경 | 기간 구독 함수 호출 52회 | 2회: 최초 빈 목록과 최초 ID 목록. 이름은 마지막 값으로 갱신 |
| 마이페이지의 같은 이름 변경 | 현재 수련회 객체 변경마다 현장 구독 재생성 | 기간 구독 2회, 조 편성 구독 1회 유지 |

차트별 effect가 자신이 만든 인스턴스만 정리하도록 나눴다. 필터에 관계없는 전체 주차·부서 월별 차트를 재계산하거나 다시 만들지 않는다. 같은 주차별 필터 조작의 Chart 생성자 시간은 로컬 1회 관찰에서 39.9ms→13.0ms였고, 수정 후 월별 학년 필터는 6.9ms였다. 이는 생성자 실행 시간으로, 전체 클릭 지연·INP·실사용 기기 성능 수치가 아니다. 전체 앱이 일정 비율 빨라졌다고 해석하지 않는다.

포털·마이페이지는 렌더 테스트에서 구독 함수를 계수했다. ID 추가·삭제·순서 변경 시에는 다시 구독하며 같은 시작일의 기간 우선순위도 보존한다. 이가드는 이름·현장 탭만 바꿀 때 데이터 구독 22개가 유지된다.

학생 원장 오류는 단순 네트워크 단절과 같지 않다. Firebase 권한 거부 콜백을 네트워크 오류로 설명하지 않으며 연결 상태 UI를 유지한다. 정상 본문이 막혀도 상단 연도 선택·로그아웃 등의 복구 동작은 유지된다. 운영 DB 자동 정리·자동 쓰기는 추가하지 않았다.

## 남은 확인 사항

- **운영 실측 미확인:** 인증 후 전체 흐름 E2E, 실제 Firebase 지연·단절, 모바일 실기기 속도, 라이브 배포 상태. 이번에는 운영 화면의 자동 쓰기를 피하고 로컬 가상 데이터로 검증했다. 앞선 공개 홈 Lighthouse 점수는 이번 패스에서 재측정하지 않았으며 인증 후 속도의 근거로 쓰지 않는다.
- **의존성 경고 미수정:** 앞선 보고서의 audit 결과와 호환성 검토가 남아 있다. 이번 패스에서는 패키지·lockfile을 변경하거나 audit를 다시 실행하지 않았다.
- **장결 집계 의미 미변경:** 전체 대시보드와 반 통계의 장결 포함 기준이 다르다. 차트 작업량을 줄이면서 기존 분모·수치·표시 순서는 유지했다. 업무 기준 확인 후 별도 결정이 필요하다.
- **기존 학생 앱 lint 경고 22개:** 타입·이미지/폰트·미사용 변수·Hook 의존성 등이다. 규칙 비활성화나 범위 축소로 숨기지 않았다.

변경과 학습 메모는 같은 로컬 브랜치에 보존한다. 이번 요청은 사용 속도·안정성 점검과 개선 범위로 처리했으며 푸시·배포는 하지 않았다. 운영 반영 시 기존 PR 검토·사용자 병합 절차 및 데모 설정 유지가 필요하다.
