# 출석부 관리자 대시보드 — 2026-09-05

## 요청과 범위

사용자는 관리자 로그인 후 Linear UI/UX를 참고한 관리 화면과 전체 배포를 요청했고, 첫 화면의 우선순위를 **주간 출석·미입력 반 중심**으로 확정했다. 앞선 프로젝트 최적화·속도·운영 안정성 보강도 같은 브랜치에 포함한다.

- 학생 앱 관리자 첫 화면 `/dashboard`, 관리 메뉴 셸, 반별 입력 현황을 추가했다. `/admin`은 기존 계정·설정 화면이다.
- 참고: [Linear의 인터페이스 개선](https://linear.app/now/behind-the-latest-design-refresh). 밝은 회색 탐색 영역, 고정된 작업 제어, 절제된 강조색과 밀도 있는 목록을 출석 업무에 맞게 적용했다.
- 운영 DB 쓰기, 데이터 형태 변경, Rules 수정·배포, 계정·권한 변경은 없다. 기존 Firebase 구독 상태를 읽어 계산하며 대시보드용 구독을 추가하지 않았다.
- 학생 데모 모드와 공용 계정·권한은 유지한다. 실제 데모 권한과 화면의 교사 역할 제한은 서로 다른 계약이다.

## 구현

- 주일 선택, 입력 완료 반·출석 인원·출석률·미입력 학생 요약, 미입력·입력 중 반 안내를 제공한다.
- 반·교사·학생 이름 검색, 부서·학년·입력 상태 필터, `/` 검색 포커스를 제공한다. 요약은 전체 범위, 목록은 필터 범위다.
- 선택한 반과 주일을 출석 입력 화면으로 전달한다. 관리자는 해당 연도의 정상 주일을 선택할 수 있고 교사·데모는 최근 4주 제한을 유지한다.
- 최초 관리자 진입은 대시보드로 안내하되 이후 메뉴·새로고침·날짜 링크를 보존한다. 교사·데모의 관리자 경로는 자식 페이지를 마운트하기 전에 차단한다.
- 입력 완료와 미입력은 장결 제외 대상 기준이다. 출석률은 기존과 같이 장결 포함 입력 기록 `O / (O + X + T)`이며 두 기준을 화면에 명시했다. 기존 통계의 업무 기준을 바꾸지 않았다.
- 데스크톱은 사이드바와 표, 모바일은 가로 메뉴와 반별 묶음으로 배치한다. 선택·포커스·오류·빈 원장·검색 결과 없음 상태를 구분한다.
- 입력률 막대는 `transform`으로 표시하며 reduced-motion을 존중한다. 신규 경로 `/dashboard`에도 기존 화면과 같은 HTML 캐시 방지 헤더를 추가했다.

## 검증 근거

루트 `npm run verify`에서 앱별 lint → typecheck → test → build를 순차 실행하고 Agent OS 테스트까지 통과했다.

| 대상 | 실제 결과 |
|---|---|
| 통합 앱 | 112개 테스트 파일, 869개 테스트 통과, lint/typecheck/build 통과 |
| 학생 앱 | 20개 테스트 파일, 249개 테스트 통과, lint/typecheck/build 통과 |
| Agent OS | 35개 테스트 통과 |
| 합계 | 1,153개 테스트 통과 |

학생 앱 lint는 0 errors / 기존 22 warnings다. 마지막 캐시 경로 보강 뒤 관련 테스트 3개를 재실행해 통과했으며, 막대 렌더 보강 뒤 lint/typecheck를 다시 통과했다. 배포 산출물은 별도의 실제 운영 설정으로 재빌드하며 공개 데모 유지 설정을 확인한다.

로컬 브라우저 QA는 실제 AppShell·AppContext·DataLoadGate·대시보드·출석 화면과 가상 Firebase SDK를 결합했다. 18개 반·405명 가상 원장이며 실제 Firebase SDK는 번들에서 배제하고 모든 쓰기 함수는 예외를 던지도록 했다.

- 관리자 로그인과 로그아웃, 기존 데모 반 선택 및 관리자 로그인 진입을 확인했다.
- 확인 필요 15개 반 필터, 검색 결과 없음·초기화, 선택한 1월 4일과 2부 3학년 2반 전달, 이후 수동 날짜 변경을 확인했다.
- 교사의 `/dashboard`, `/admin`, `/overall` 차단과 자식 페이지 미마운트, 최근 4주만 선택 가능한 상태를 확인했다. 데모도 관리자 대시보드 접근이 차단된다.
- 원장 오류·명시 재시도·복구·빈 원장 안내를 확인했다. 모든 QA 상태에서 차단된 쓰기 호출도 0건이었다.
- 데스크톱과 375px 모바일에서 화면을 확인했고 페이지 전체 가로 넘침은 없었다. IAB 캡처·일부 조작이 불안정해 시각·로그인 검증은 Chrome에서 확인했다.
- 디자인 detector는 1회 실행했다. 유일한 경고인 width 애니메이션을 transform으로 수정했다.
- 독립 UI 검토자가 같은 가상 화면을 데스크톱·모바일에서 다시 확인했고 출시를 막는 결함을 발견하지 않았다. 스크린샷 파일 저장 제한 때문에 CUA 직접 확인으로 대체했다.

실제 Firebase 장애, 모바일 실기기, 실제 관리자 계정 인증 후 운영 화면은 이 가상 QA의 검증 범위가 아니다. 통합 앱 인증 E2E는 저장소의 인증 상태 secret이 필요하며 인증 가드를 우회하지 않는다.
