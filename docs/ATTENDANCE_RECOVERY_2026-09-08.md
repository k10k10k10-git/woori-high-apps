# 출석부 복구·동시 작업 개선 — 2026-09-08

## 반영 내용

- 학생·반 삭제: 기존 형태의 복구 사본을 먼저 확정하고 명단이 사전값과 일치할 때만 트랜잭션으로 제거한다. 학생 삭제는 다른 학생·반 메타데이터를 보존한다. 반 삭제는 반 전체 변경을 감지한다. `attendance`를 쓰거나 지우지 않는다.
- 복원: 기존 학생 ID·반 키로 남아 있는 출석을 다시 연결한다. 현재 출석값을 과거 사본으로 덮지 않는다. 삭제 목록에서 보관 출석 건수를 표시하고, 없으면 과거 삭제 기록을 복원할 수 없음을 안내한다. 복구 사본의 영구 삭제도 출석을 자동으로 지우지 않는다.
- 응답 실패: 사본 저장이 확인되지 않으면 명단 제거를 시작하지 않는다. 명단 제거 응답을 잃으면 사본을 유지하고 현재 명단 확인을 안내한다. 명시적으로 거절된 경우만 이번 사본 정리를 시도한다.
- 콜드 캐시: Firebase SDK에서 get만 한 뒤 트랜잭션을 실행하면 첫 callback이 null이라 기존 명단을 없다고 판단할 수 있었다. 공통 `lib/db.ts`가 트랜잭션 완료까지 onValue 구독을 유지하고 오류·완료 시 해제한다.
- 다른 탭: 동일 출처 Web Locks에서 일반 쓰기는 shared, 시트 동기화 전체는 exclusive로 실행한다. ifAvailable로 대기 중 오래된 쓰기를 쌓지 않고 재시도를 안내한다. 지원하지 않는 브라우저에서는 동기화를 차단한다. 출석 저장에는 충돌 이유와 재시도 버튼이 남는다.

## 경계

운영 DB 직접 쓰기·Rules 변경/배포·계정 변경·기존 데이터 이관 없음. 공유 데이터 형태·경로와 통합 앱 새친구 되돌리기 로직은 변경하지 않았다. 이미 삭제된 과거 출석을 복원하지 않는다.

보관 출석은 원래 경로에 남으며 해당 학생 명단 복원 시 조회에 다시 포함된다. 명단 교체나 새로운 명단 추가에 과거 학생 ID를 다른 사람의 ID로 재사용해서는 안 된다. 기존 명단 충돌 방어와 새 학생 UUID 계약을 유지한다.

Web Locks는 같은 출처·브라우저의 새 버전 클라이언트 범위다. 다른 기기·구버전·직접 SDK 요청과 서버 Rules 권한 폭을 해결했다고 설명하지 않는다. 운영 전체 인증 E2E는 이번 로컬 인증 토큰 기반 에뮬레이터 및 실제 컴포넌트 검사와 별개다. 모의 로그인 UI를 실제 Firebase Auth 로그인 성공으로 보고하지 않는다.
