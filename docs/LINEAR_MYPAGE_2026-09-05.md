# 통합사이트 마이페이지 개편 — 2026-09-05

## 목적과 기준

로그인 후 마이페이지에서 내 사역·요청 상태를 찾고, 관리자는 승인 대기와 사이트 요청을 바로 처리할 수 있도록 화면 구성을 개편했다. 출석부 관리자 화면에서 사용한 좌측 메뉴, 간결한 상단 위치 표시, 조밀한 통계와 목록 구성을 통합사이트에 맞췄다.

참고한 [Linear My issues 공식 문서](https://linear.app/docs/my-issues)는 개인에게 관련된 업무를 한곳에 모으고, 업무 종류와 우선순위에 따라 살펴보는 구성을 설명한다. 이번 앱에는 이를 개인 사역과 요청 중심으로 적용했다. 통합사이트의 녹색 브랜드와 기존 기능·권한 체계를 유지했으며, 별도 이슈 관리 시스템이나 새로운 DB 구조를 추가하지 않았다.

## 화면 구성

| 화면 | 변경 내용 |
|---|---|
| 공통 마이페이지 | 데스크톱은 좌측 메뉴·상단 현재 위치·독립 본문 스크롤로 구성한다. 작은 화면에서는 메뉴를 가로로 전환하고 전체 화면 모달을 사용한다. |
| 대시보드 | 관리자는 처리 대기 통계, 승인·요청 통합 처리함, 운영 상태와 최근 해결 내역을 확인한다. 일반 역할은 자신의 일정·요청·배정과 사역 바로가기를 확인한다. |
| 내 사역 | 학기 배정·출석, 주일 팀, 수련회 조·현장 담당을 기존 자료에서 확인한다. |
| 내 요청 | 본인이 제출한 요청의 처리 상태와 해결 메모를 확인한다. |
| 팀원 관리 | 기존 학기·방학 역할 배정, 접근 승인·거절, 팀원 검색 기능을 보존한다. 허용된 관리자에게만 보인다. |
| 요청사항 | 접수 상태별 목록에서 요청을 선택하고 상세 내용·해결 메모를 확인한다. 기존 해결·삭제 흐름을 사용한다. |

기존 마이페이지 진입점과 `initialTab` 사용 방식을 유지한다. 실제 표시 권한은 `accessPolicy.ts`의 능력 함수가 결정하며, 계정이나 역할이 바뀌면 열린 마이페이지의 이전 상태를 폐기한다. 화면 권한이 Firebase Rules의 세부 데이터 접근 범위와 같다는 의미는 아니다.

## 안정성과 접근성

- 선택한 패널만 `React.lazy`와 `Suspense`로 불러온다. 팀 관리 등 무거운 패널을 개인 대시보드 진입 때 전부 렌더하지 않는다.
- 내 사역의 첫 준비 상태는 필요한 구독 응답을 함께 확인한다. 계정·학기·수련회가 바뀌면 이전 대상의 자료를 숨기고, 해제된 구독의 늦은 응답을 무시한다.
- 처음 조회 중이거나 오류가 있으면 `0건`, 일정 없음, 미배정으로 확정하지 않는다. 빈 목록은 정상 조회 결과가 확인된 뒤 표시한다.
- 내 요청도 계정별 상태를 분리하고 구독 해제 이후 응답을 차단한다. 실패는 무한 로딩이나 전송한 요청 없음과 구분한다.
- 기존 `OverlayShell`의 모달 이름·포커스·ESC 닫기 계약을 사용한다. 메뉴와 본문은 ARIA로 연결하고 방향키·Home·End 이동을 제공한다.
- 사역 바로가기의 일반 클릭은 마이페이지를 닫고 해당 화면으로 이동한다. 수정 키를 누른 새 탭 열기 등 기존 링크 동작을 보존한다.

구현은 `MyPageModal.tsx`, 관리자·개인 패널, `useMyPageData.ts`, 공통 오버레이와 헤더에 들어 있다. 마이페이지 전용 스타일은 `src/app/my-page-workspace.css`로 분리한다. 학생 출석부의 코드·데모 설정은 이번 개편 범위에 포함하지 않는다.

## 검증 경계

브라우저 확인에는 실제 운영 컴포넌트와 CSS를 불러오는 별도 Vite fixture를 사용했다. Auth/UI 및 DB 모듈 경계에 합성 응답을 제공하고, 실제 권한 정책·파생 훅·패널의 동적 로딩은 그대로 실행한다. 운영 라우트에 인증 우회를 넣지 않는다.

- 운영 DB 직접 쓰기: 수행하지 않음. Rules·계정·권한 레코드 변경도 없음.
- fixture의 Firebase SDK: import 단계에서 차단한다. 실제 Vite 모듈 그래프 확인에서도 Firebase 런타임 모듈은 0개였다.
- 쓰기 함수는 명시적 차단 오류를 반환하고 가상 확인창은 취소한다. 외부 연결은 CSP로 막는다.
- 이름과 이메일은 합성 값이며 실제 사용자의 인증 정보나 운영 데이터를 사용하지 않는다.
- 합성 브라우저 검증은 실제 운영 계정의 로그인 성공이나 운영 DB에서의 저장 성공을 보증하지 않는다.
