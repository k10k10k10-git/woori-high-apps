# 출석부 관리자 화면 통합 — 2026-09-06

사용자는 기존 관리자 대시보드와 전체 현황을 하나로 합치고, 명단·계정 설정을 같은 Linear UI로 개편해 운영 배포하도록 요청했다. 장결자 관리는 구현 방법을 제안하는 범위다.

## 구현

- 관리자 메뉴를 `전체 현황 / 출석 입력 / 학생 관리 / 반별 통계 / 계정·설정`으로 통합했다. `/dashboard`와 이전 `/overall` 주소는 같은 `OverallTab`을 표시하고 활성 메뉴도 공유한다.
- 전체 현황은 `출석 현황 / 교사·학생 명단 / 건의사항`으로 구성한다. 주간 지표와 반별 입력 상태를 먼저 표시하고 연간 추이는 펼칠 때 로드한다. 네 차트와 반별 누적률을 보존했다.
- 입력 완료·미입력은 장결 제외 일반 학생, 전체 출석률은 장결 포함 O/(O+X+T)를 유지한다. 반별 누적률은 기존의 학생별 백분율 평균이며, 다른 페이지의 학기 선택에 영향받지 않도록 연간으로 고정했다.
- 명단은 간결한 교사 표와 학생 목록으로 정리하고 기존 내보내기·명단 수정 기능을 유지한다. 교사 목록의 실패 안내·재시도와 늦게 도착한 이전 조회 응답 차단을 추가했다.
- 건의사항은 반별 최신 의견과 펼침 목록으로 정리했다. 조회 중·실패·재시도를 구분하고 삭제 오류를 안내한다. 사용자 확인 후 동일 경로의 건의사항 한 건만 삭제하는 계약을 유지한다.
- 계정·설정은 계정 관리·특별 일정·데이터 관리로 구분하며 검색·역할 필터와 키보드 탭 탐색, 계정 대화상자를 제공한다. 기존 계정·행사·시트 동기화·진급의 저장 경로를 유지한다.

## 데이터·권한 범위

`classes/{year}`, `attendance/{year}`, `events/{year}`의 기존 구독 상태를 사용한다. 필요 화면에서 `teacher*`, `userRoles`, `suggestions/{year}`, `config/sheetSync`를 읽는다. 명단·계정·일정·동기화·진급의 기존 명시적 실행 버튼은 남아 있다. 작업 중 운영 DB 직접 쓰기·Rules 수정/배포·Firebase Auth 및 권한 레코드 변경은 하지 않는다. 데모 빌드 설정을 유지하고 운영 배포 대상은 학생 출석부 Hosting뿐이다.

## 장결자 관리 제안 — 미구현

1. **장결 명단**: 이름, 부·학년·반, 담임, 최근 참석(O/T), 최근 8회 출석과 기존 이력을 한곳에 모은다. 현재 데이터에 없는 장결 지정일·연락일은 임의 생성하지 않는다.
2. **연속 결석 확인**: 기준 주일까지 행사·휴일을 제외한 최근 3회가 모두 X면 확인 대상, 4회면 우선 연락 후보로 표시한다. O/T는 연속 결석을 끊고 빈칸은 미입력 확인으로 구분한다. 자동 장결 지정은 하지 않는다.
3. **확정·복귀**: 시트와 앱 중 장결 상태의 기준을 먼저 정한 뒤 담당 관리자가 지정·복귀를 확정한다. 학생 SID·personId·출석은 유지하고 삭제 후 재등록하지 않는다. 기존 학생의 앱 확정 상태를 우선하며 시트와의 차이를 동기화 미리보기에서 확인하는 정책을 권한다.
4. **연락·돌봄 기록**: 상태 변경 일시·처리자부터 최소한으로 기록한다. 상담·가정·건강 상세는 공유 `classes`와 `adminChanges`에 넣지 않는다. 비공개 경로·Rules·조회 권한 설계는 후속 확인 대상이다.

### 구현 전 확인한 제한과 기존 결함

- `src/lib/sheetSync.ts`는 시트의 번호가 다시 시작되는 구역에서 `jang`을 파생하고 동기화 시 해당 값을 다시 적용한다. 수동 지정 UI만 추가하면 다음 동기화에서 되돌아간다.
- 과거 시트 빈칸이 X로 변환되는 경로가 있으므로 현재 X만으로 명시 결석과 미입력을 완벽히 구별하지 못한다. 후보는 교사 확인을 거친다.
- **P1·미수정**: `src/components/modals/StudentModal.tsx`의 `handleSave()`는 학생 객체를 새로 구성하면서 기존 `jang`을 복사하지 않는다. 장결 학생의 일반 정보 수정으로 상태가 유실될 수 있다. 장결 관리 구현에 앞서 기존 상태 보존 회귀 검증과 함께 수정해야 한다. 이번 관리자 화면 개편에서 이 모달의 저장 동작은 변경하지 않았다.
- 현재 장결 플래그가 과거 통계 필터에도 적용된다. 시점별 기준을 보존하려면 상태 이력이 필요하다.
- 통합 앱도 `jang`을 수련회 명단 분리·주일 출석·검색에 사용한다. 필드 의미 변경은 `DB_OWNERSHIP.md`에 따른 두 앱 영향 확인이 필요하다.
- `SHOW_ATTENDANCE_RISK_SECTIONS=false`는 그대로 유지한다.
