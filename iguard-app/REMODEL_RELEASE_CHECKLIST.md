## 4. 로그인 후 리허설 QA

운영 데이터를 바꾸지 않는 읽기 확인부터 하고, 쓰기 시나리오는 연습용
수련회에서만 진행한다.

### 4.1 모바일·화면

- [ ] iPhone 또는 375×812 Chrome에서 가로 넘침이 없다.
- [ ] 조별 정보에서 방별 학생 이름을 찾을 수 있다.
- [ ] 개인 큐카드 한눈에 보기와 현재·다음 고정 카드가 함께 읽힌다.
- [ ] 핵심 탭·버튼은 손가락으로 오조작 없이 누를 수 있다.
- [ ] 긴 이름·긴 포스트·긴 구간명이 겹치거나 잘리지 않는다.

### 4.2 큐싯 저작

- [ ] 빈 연습 수련회에 이전 수련회의 **구조만 복제**한다.
- [ ] 담당자·조·버스·GBS·메모가 복제되지 않았음을 확인한다.
- [ ] 시간 블록 3개를 만들고 각 블록에 구간·포스트를 추가한다.
- [ ] 담당자, 미정 슬롯, 비스탭 주체, 선밥/후밥, 상세, 메모를 저장한다.

- [ ] 개인 큐카드의 현재·다음이 진행 마커를 우선한다.
- [ ] 사용자가 고른 스탭과 펼침 상태가 시계 갱신 때문에 바뀌지 않는다.

## 5. 초보 제작자 관찰 테스트 — P5 운영 완료 조건

이 검증은 자동화하거나 개발자가 대신 통과시킬 수 없다.

1. 큐싯을 만들어본 적 없는 스탭 1명을 섭외한다.
2. 설명 없이 “다음 수련회 큐싯 초안을 만들어보세요”라고만 말한다.
3. 30분 동안 도움을 주지 않고 아래를 기록한다.
   - 멈춘 화면과 지점
   - 질문 횟수와 질문 내용
   - “시트를 열고 싶다”고 말하거나 실제로 연 시점
   - 완성한 시간 블록 수
4. **설명 없이 블록 3개 이상을 구간·포스트까지 채우면 통과**한다.
5. 실패하면 해당 화면을 수정하고 다른 사람으로 다시 시험한다.

관찰 테스트 통과 전에는 P5의 **코드 구현만 완료**이며, 운영 전환은
완료로 표시하지 않는다.

## 7. 사전 선언 롤백 조건

다음 중 하나라도 발생하면 현장에서 임의로 버티지 않고 시트 병행으로
즉시 돌아간다.

- 동선 수·구간 참조가 맞지 않거나 담당자가 사라짐
- 블록·구간·포스트 생성 또는 저장 불가
- 동시 편집이 다른 사람의 변경을 지움
- 현재·다음 큐카드가 실제 진행과 다른 블록을 가리킴
- 명찰카드에서 필수 명단이 누락됨
- 승인된 사용자가 로그인 또는 PIN 통과 후 화면에 들어갈 수 없음

복구 순서:

1. **운영 전환 롤백**: 해당 수련회는 기존 시트를 병행하고 앱 편집을 멈춘다.
2. **앱 롤백**: Vercel의 직전 Ready 배포로 되돌리거나 문제 커밋을 revert한다.
3. **DB 이관 롤백**: 위 2장의 해당 `RESTORE.txt` 명령으로 그 수련회의
   경로만 복구한다. 전체 `retreats` 노드를 덮어쓰지 않는다.
4. Firebase Rules는 이 작업의 롤백 대상으로 삼지 않는다.
