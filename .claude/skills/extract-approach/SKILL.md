# extract-approach — 풀이 접근법 녹음기

방금 해결한 문제의 **풀이 과정**을 학습 메모 1개로 추출해 리포에 저장한다.
세션이 끝나는 순간 접근법은 증발한다 — 이 스킬이 그걸 자동으로 녹음해, 이후의 (더 약한) 모델이 같은 문제를 처음부터 다시 풀지 않게 한다.

## 언제 실행하나
- "사소하지 않은" 문제를 푼 직후: 3회 이상 시도했거나, 원인이 비직관적이었거나, 우회로를 찾았거나, 도구/환경의 함정을 밟았을 때.
- 단순 오타 수정·기계적 치환·이미 문서화된 패턴의 반복 적용에는 실행하지 않는다 (메모 인플레이션 방지).

## 메모 형식 (4항목 고정 — 전부 채울 것)

```markdown
### <문제를 한 줄로> (YYYY-MM-DD)
- **접근법**: <간단한 분해 단계 — 1→2→3, 각 단계는 실행 가능한 동사로>
- **판단 질문**: <무엇을 하지 않았고, 왜 안 했는지 — 기각한 대안과 기각 사유>
- **재사용 규칙**: <다음에 비슷한 상황이면 이렇게 하라, 한 줄>
```

작성 기준: **추위에 읽는 사람(약한 모델)용으로 쓴다** — 이 세션의 맥락 없이 읽어도 따라할 수 있어야 한다. 파일 경로·명령어는 구체적으로, 대명사("그 파일", "아까 방법") 금지.

## 저장 위치 (이 리포의 기존 관례와 통합 — 중복 시스템 금지)

1. **특정 앱의 코드 패턴에 관한 교훈** → 그 앱 `CLAUDE.md`의 "핵심 코드 패턴" 섹션에 번호 이어서 추가 (기존 패턴 1~17과 같은 방식).
2. **앱과 무관한 워크스페이스·도구·환경 교훈** (git, Vercel, macOS, Claude Code 자체 등) → 리포 루트 `LEARNINGS.md`에 위 형식으로 append (없으면 `# 학습 메모 — 풀이 접근법 기록` 헤더로 생성).
3. **사용자 선호·작업 방식에 관한 교훈** → 메모리(`user`/`feedback` 타입)로 — 리포에 넣지 않는다.

같은 교훈이 이미 기록돼 있으면 새로 쓰지 말고 기존 항목에 날짜·보강 내용만 덧붙인다.

## 완료 처리
- 메모를 저장한 뒤, 진행 중이던 커밋이 있으면 같은 커밋에 포함하고, 없으면 `문서: 학습 메모 — <한 줄>`로 별도 커밋.
- 마지막에 한 줄 보고: "학습 메모 저장됨 → <파일>:<섹션>".
